## 1. Tell us about your school

Request a demonstration on site in Vilnius County, or a Zoom call with questions and answers elsewhere. Tell us about your Windows PCs, network, number of labs and the actions you need.

## 2. Receive a test package

There is no public download. After the demo, arrange a package for your school and identify the exact version being tested. Windows 10 and 11 configurations have been used in testing; compatibility depends on edition, patch level, policy and the actions required. This is not a promise of continuing vendor support for an older operating system.

## 3. Pilot one teacher PC and one Client

Use school-owned test machines, not the full student lab. Have an IT administrator install the Host and Client, restrict the network path, set up separate access roles and verify the package's endpoint-trust controls.

Try the actions your school needs with synthetic files. Check Teacher denials, key revocation, lock/unlock, restriction restoration, file collection, logs and reconnect behavior.

## 4. Rehearse recovery before expansion

Keep an independent way to reach the machines and a known-good installer. Client self-update does not yet automatically roll back after a failed start. Test update verification and the manual recovery procedure before applying an update to a room.

## 5. Agree the rollout

Record the tested version, acceptance results, named owner, support scope, key custody, data retention and recovery steps. Roll out in small batches using the agreed installation package.

A successful demo is not a security sign-off for the whole school. [Review the IT notes](../security/) and [pricing](../pricing/), then [request a demo](../request/).
